# R2 storage and credentials

Cratepin stores immutable originals under the configured project namespace and raw SHA-256.
The committed source lock selects exact keys, hashes and byte counts; builds never choose
inputs from a remote listing or latest catalogue. ETags and object metadata do not substitute
for hashing the actual bytes.

## Credentials

Configuration contains environment variable names, not secrets. Set their values in the
calling environment; the CLI does not automatically load .env files. See the
[R2 configuration](../contracts/config.md#r2) and repository .env.example template.

Author push uses bucket-scoped writer credentials. Build-side pull uses a distinct
read-only pair with s3-readonly, or no credentials with public-http and its configured
non-secret HTTPS base URL. Both transports verify locked SHA-256 and length before accepting
an original. Scope permissions at the storage provider; using different variable names alone
does not establish read-only authority.

The endpoint is the R2 account HTTPS origin, or that origin followed by the configured bucket;
the latter is normalized to the account origin. Requests use SigV4 with region auto.
Redirects are refused. Warm-cache reads resolve no credentials; --offline never creates a
remote connection. Missing variables are reported by name, and resolved secrets are redacted.
Never put writer credentials in application output or an install/prebuild hook.

## Push

Review push --dry-run before an author upload. Removing logical IDs requires
--confirm-removals; this removes references from the next lock, never remote objects.
Uploads use create-only writes, including multipart completion. Existing keys are not replaced.
Every referenced object is read back and verified before the lock is replaced. A failure leaves
the previous lock intact; successfully uploaded objects may remain unreferenced for a later run.

Source changes during transfer fail integrity checks. Cancellation stops pending work and
attempts to abort owned multipart sessions. A killed process or an initiation whose response
was lost may leave an unknown incomplete upload; manage the bucket's incomplete-upload lifecycle
separately. Concurrent pushes on the same checkout are unsupported.

## Pull

Only locked keys are retrieved. Each downloaded original is streamed, hashed and counted before
becoming a verified cache entry. --offline reports cold or corrupt entries as failures rather
than substituting local source files or contacting storage. --restore-sources is explicit and
writes missing source files only; it never replaces existing author files.

Transfer concurrency, timeouts, attempts and multipart sizes are bounded by
[configuration limits](../contracts/config.md#limits). Only transient transfer failures are
retried. Cancellation removes owned partial local files. See
[backup and recovery](../operations.md) for independent original-byte retention;
remote deletion is unavailable.
